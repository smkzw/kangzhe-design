# 03 字号、中文表达、观点与引用

## 字号 TYPE-01
数值见 `tokens.type_pt` / `type_px`（PPTX 用 pt，HTML-PPT 用逻辑 px，换算 1pt = 4/3px）。正文页的基准：

| 角色 | PPTX | HTML-PPT 逻辑 px |
|---|---|---|
| 页标题 | 24pt | 32 |
| 卡标题 | 18pt | 24 |
| 正文（standard） | 15pt | 20 |
| 正文下限 / compact 整页 | 12pt | 16 |
| 辅助文字（secondary） | 12pt | 16 |
| 观点句 | 18–20pt | 24–26.67 |
| 说明文字（reference，唯一可小于 12pt） | 10.5pt | 14 |

站点式与流式（`body_profile: responsive`）的基准，单位为 CSS px：

| 角色 | 字号 |
|---|---|
| 首屏标题 h1 | `type_px.site_h1_min`–`site_h1`（32–44，随视口宽度） |
| 卡标题、舞台标题 | `card_title`（24） |
| 导语、正文 | `site_body`（18） |
| KPI 数值 | `kpi_value_min`–`kpi_value`（28–38） |
| KPI 标签、状态条说明、导航、正文下限 | `site_body_floor`（16） |

封面、目录、章节、尾页使用 11 的专用字号，不套这里的页标题。听众必须读的表体、数据标签、示意图标签、按钮、编辑字段和下钻文字不低于正文下限 12pt；坐标刻度、图例、脚注与来源可用说明文字 10.5pt。

**辅助文字 secondary**（`type_pt.secondary` / `type_px.secondary`）
- 承担表体、数据标签、示意图标签、卡内旁注、状态条与演示舞台的标签。
- 任何页都可以用，不必整页切成 compact。卡标题、正文与页标题不受影响。
- page-plan 的文本角色写 `secondary`，HTML 用 `.kz-text-secondary` 或 `data-kz-role="secondary"`。
- 不能用来承载正文论点，也不能把放不下的正文改标成 secondary。
- 页脚是固定的页面框架（13.5pt），不属于这个角色。

**说明文字 reference**（`type_pt.reference` 10.5pt / `type_px.reference` 14）
- 只承担不需要逐字读的辅助说明：脚注、来源与参考文献、图注、坐标刻度、图例、样本量（n=）、风险人数行、表格下的缩写说明。
- 这是全局最小字号：任何文字不低于 10.5pt，`tools/check_kz_project.py` 的 FONT-FLOOR 按它报错。
- 正文、条款、表体、示意图标签、卡标题都不能放进这个角色；正文不低于 12pt。

- **同页同角色只有一个字号、一个行距、一套间距。** compact 是整页正文档，不是挤不下时给单卡用的开关；降档在 page-plan 写原因。
- HTML-PPT 的 px 是逻辑画布单位：实际 computed 字号 ÷ `--kz-un` 的使用值来核对（`--kz-un` 由 html-ppt-bridge 维护，见 adapter）。
- 站点式 / 流式可声明 `body_profile: responsive`，在页面或共同阅读区统一设定 `--kz-type-body`（默认站点正文 `type_px.site_body` 18px），仍守 16px 下限与同角色一致；PPTX 与 HTML-PPT 不接受 responsive。
- PPTX 中文 run 用微软雅黑，纯数字/英文 run 可用 Arial（ppt-master 主题字体 latin Arial / ea Microsoft YaHei 即满足）。字体不可用写成环境失败，不分发字体文件。

## 容量溢出的处置顺序 TYPE-03
删重复与无关 → 精简非事实性修饰 → 扩大可用区域或重排网格 → 主层/明细分层（关键限制留在主层） → 拆页 → 最后才整页 compact。禁止逐卡缩字、压缩单卡行距、CSS scale 文本、ellipsis、line-clamp、隐藏裁切、把必要限制只放在悬停里。

同一段落在 PPTX 用一个文本框的多段落/多 run，不每行一个文本框；同级并列卡的标题基线与首行基线一致；不靠插空段落伪造行距。

## 断行与孤字 TYPE-04
末行只剩一个汉字（可带标点）即孤字行，必须消除：调整自然断句、共同阅读宽度或段落排版，使末行含完整词组。不逐卡缩字、不压行距、不添字凑行、不用 keep-all 造成长中文溢出。

- HTML：正文 `p/li/td/th` 默认 `text-wrap: pretty`，标题和短标签 `text-wrap: balance`（kz-glass.css 已设）。这是手段，不是证明——以 `KZLayoutQC.inspectOrphans` 在每个交付视口、电影的各阅读状态实测为准。换行落在词内部（“中心记｜录”“实验室｜数据”）同样不合格：先缩短或改写成短语、放宽共同阅读宽度，`inspectOrphans` 的 `splits` 报出这类拆词。
- 数字与单位、比较符号与阈值、日期与锚点、完整否定或条件短语尽量不拆开；短词组 `nowrap` 前先量真实宽度，长条件句照常换行。
- 同一重点的相邻文字统一字重和颜色，标点保持正文样式；展示层的拆分不改写源数组、否定、且/或与日期。
- PPTX 按真实字体与文本框在 PowerPoint 中核对。

## 标题与文字分工 COPY-01
| 角色 | 职责 | 示例 |
|---|---|---|
| 页标题 | 这一页属于哪一章、讲哪个主题（名词短语） | 入排标准；研究设计；XX研究结果 |
| 卡标题 | 类别、指标或对象名 | 研究人群；主要终点 |
| 正文 | 材料支持的事实、关系、限定 | 每条一个完整意思，保留数字与条件 |
| 观点句（可选） | 听众应理解的本页含义 | 不重复一串数值 |
| 讲者备注 | 解释、限定、衔接 | 不把整页再读一遍 |

页标题回答“这一页讲的是哪一部分”，不回答“这一页想说明什么”。它是章节或主题的名词短语，听众扫一眼就知道讲到方案的哪个位置；本页的观点、结论、待讨论的问题放在观点句、结论带或讨论题卡里，不放进标题。

- 不写结论、趋势、判断或问句；不用冒号、破折号、逗号、句号、问号（项目代码里本来的半角连字符不算）。
- 一般不超过 14 个汉字；同一主题分几页时用同一个标题，或在后面接分主题名（“排除标准 既往治疗与洗脱”），不写“续”。
- 不靠缩字或省略号塞进固定框；先短写研究名称，全称放正文。
- 即使参照稿或用户旧稿用了“主题：结论”的写法，也按本条改写。`tools/check_kz_project.py` 的 TITLE 检查报出冒号、破折号、句读与超长标题。

不合格：“研究结果：疗效显著提升”“入排标准——精准识别人群”“二甲双胍稳定用药如何界定？”“双主要终点支撑注册”。合格：“XX研究结果”“入排标准”“讨论题 二甲双胍稳定用药”“研究终点”。

## 卡内层级 COPY-06（PPTX / HTML-PPT 必验）
普通文字卡必须有独立、可见的卡标题和分条正文，不能把一整段材料塞进卡里。

- 卡标题用 card_title 角色、加粗、深墨色；与正文在字号和字重上都可区分，不能只靠位置或冒号，也不能把标题混进第一条 bullet。电影的每个业务阅读态同样适用。
- 两个及以上并列事实、步骤或限制用分条；一条一个完整意思，保留数字、单位、时间窗、否定、且/或和例外；条件与结果不拆成会改变关系的两条。一般 2–4 条，这是容量建议，不是删事实的上限。完整原文必须连续引述时记为 `verbatim_quote`，写明源位置与理由。
- HTML 用真实 `h3`（或同等语义标题）与 `ul/ol/li`，保留标记和悬挂缩进。PPTX 用原生标题与原生段落；ppt-master 会把 `• ` 前缀转成原生项目符号（`a:buChar`）加悬挂缩进，这是首选形式。
- 能改变理解的重点必须做文字强调：普通重点加粗，关键否定、风险、阈值、待确认按 COPY-04 用深红。没有合理重点的卡记 `not_applicable` 与理由，不机械染红。标题加粗不计正文重点。
- 图表、表格、甘特的数据区、单值 KPI 和四类 hero 页用各自角色合同，不为满足分条把单元格硬改成列表。站点/流式的详细阅读区允许连续段落。

## 卡内装饰图 COPY-07
生成图只作卡片装饰、不承载唯一信息时：图固定在卡的一侧，向文字侧渐变到近白，文字落在近白侧；同页并列卡的图文方位一致。不整卡铺图再压暗，不用遮罩把图擦到不可辨。证据图、图表、表格、医学影像不适用本条。纯文字卡仍是默认，本条不催生新图。

## 观点句 COPY-02
每页先明确 `takeaway: null` 或文本加材料依据；研究基本信息、流程总览、原文规则表完全可以没有观点句，没有时把空间还给正文。存在时只传达一个被材料支持的含义：不新增临床外推、不暗示因果、不把方法学警告包装成结论；居中、比正文大一档、短到一眼读完；不重复卡内数字，不写“本页展示……”“请重点关注……”。

## 中文 COPY-03
面向严肃场景：自然的中文名词和完整短句，不用直译词序、空泛大词或对工程代理说话的口吻。卡标题不用“输入/输出/抓手/赋能/闭环”代替具体医学含义（材料确在讨论接口或数据流时按专业含义保留）。不用“硬核”“一键起飞”“颠覆”“全面领先”之类宣传腔。英文缩写首次出现按受众需要解释；既定医学名称、研究编号、量表名保留，未给译名的专名不臆造。原文规则类内容保留原编号、逻辑连词、阈值、时间窗和例外；概览页只能在完整原文页之外另加，并标明是概览（COPY-09）。生成稿不对附带临床资料做医学纠错。

## 不把边界声明当内容 COPY-08
受众可见层（标题、卡标题、观点句、bullet、注脚、讲稿、弹层正文与表格）不把边界声明当内容：如“AI 不替代医学判断”“最终由人确认”“仅供参考”“本页不构造……”“规格未定义……”。判定只问两件事：删掉它是否妨碍读者完成信息任务，是否改变读者的下一步操作。两问都答“否”就删除，或移入私有 fact-map。定义审核顺序与责任动作的业务规则（如“AI 结果供双专家终审参考”“驳回原因必填”）是业务内容，保留。源材料中的边界条款如实登记在私有文件。

## 强调 COPY-04
强调词汇四种：加粗（普通重点）、深红（关键结论、风险、阈值、关键否定、待确认）、下划线（需要回到原文核对的条款位置或定义词）、高亮（本页要讨论或待决的那一处）。模板数据里分别写 `**…**`、`!!…!!`、`__…__`、`==…==`；加粗文字（结论带、卡标题）里的加粗显示为强调色 `colors.focus`，否则看不出来。PPTX 的高亮先写哨兵色，导出后由 `tools/bind_highlight_pptx.py` 改成原生高亮；HTML 用 `<mark>`。普通重点先加粗。深红 `#C00000` 只用于真正改变理解的关键结论、风险、阈值、关键否定或待确认内容；观点句一般一组、最多两组红词，普通 bullet 最多一组；不让整句染红，不让颜色承担唯一语义。

## 引用 COPY-05
受众页面只为外部科学论文和权威指南、共识、指导原则设参考文献式标注。内部方案、IB、会议纪要、台账、用户附件、内部数据汇总以及普通新闻/网页/登记库，默认不在页面上写“来源于……”或文件名。科学限定照常保留：研究名称、人群、时间点、终点定义、分析集、样本量、单位、估计量、区间。文献信息只写已核实的部分，不臆造作者、卷页或 DOI。私有 source-ledger 记录全部事实的材料位置。用户要求公开技术报告时，引文按该报告的要求处理。

## 纵向利用 TYPE-02
先按固定字号量真实内容，再定卡片高度与分组，禁止先画一排满高空壳再把三行字塞进左上角。每张卡在 page-plan 声明 `layout_mode`：

- `stack`：密集段落或原文规则，自上而下，段间距统一；放不下就拆页。
- `distributed`：2–4 个有语义的组，组间弹性间隔有上限（`layout.group_gap_max_px`），组内正常行高。
- `centered`：短事实、单值、观点句；内容作为整体在阅读区居中，并列卡以最长组对齐标题。允许低占用。
- `compact`：缩短卡高或换行列组合，是几何模式，不是缩字。

测量用文字 Range 与真实图表绘图区，排除背景、边框、阴影和隐藏节点（`KZLayoutQC.inspectCard`）。预警阈值读 `tokens.layout`：下空白主导且 `|T−B|/H > vertical_imbalance_warning`，或 `stack` 满高卡的占用跨度 `R < card_span_warning`，须修复或由独立审阅写明豁免。正文区整体占用跨度目标 `content_span_target`（70–92%），是诊断，不要求编造事实达标。修复顺序：确认内容量 → 选模式 → 统一组间距 → 缩短卡高或换网格 → 重排或拆页。不加空行、重复观点句或无依据的小标题。

PPTX 没有浏览器可量，模板页（13 BODY-02）由 `tools/kz_layouts` 按微软雅黑实测字宽求解：组间与条目间的弹性间隔各有上限（`layout.templates.group_gap_max`、`item_gap_stretch_max`），剩余高度上下平分，所以卡内文字不会全部贴在卡顶。手写页面按同一规则排。

## 原文保真 COPY-09（PPTX / HTML-PPT）
抽取前先给每段材料定类别，类别决定能不能改写：

| 类别 | 例子 | 处理 |
|---|---|---|
| 原文条款 | 入选/排除标准、禁用与允许用药、访视窗、给药与停药规则、终点定义、SAE 与 AESI 定义、方案原文表格与脚注 | 逐字保留：编号、阈值、单位、时间窗、且/或、例外、括注都不动；编号与上下级照方案（引导语和它的子项是一条）；放不下先密排、再换模板、再拆页，拆页编号接续，不写“续” |
| 数据 | 研究结果、样本量、统计量 | 数值与限定原样保留，可改成表格或图表 |
| 叙述 | 背景、理由、讨论要点 | 可以分条、改写成短句，但不删条件和例外 |

原文条款页不做摘要、不合并条目、不把“或”改成顿号、不把括注删掉；SoA 不合并评估行。需要概览时，在完整原文页之外另加一页并标明是概览，概览不能代替原文页（COPY-03）。COPY-06 的“一般 2–4 条”是叙述类的容量建议，对原文条款无效。

**篇幅与原文冲突时原文优先。** 用户给的页数（“约 20–25 页”）是叙述页的预算，不是压缩条款的理由：原文条款排不下时加页，或把整段原文放进附录页并在正文页标出位置，并在交付汇报里写明实际页数和原因。不为凑页数删条款、合并条款或改成要点。

**编号与层级取自 Word。** 方案的条款编号（1. 2. 3.）和子项层级存在 Word 的自动编号里，转成 txt / md 后字还在，编号和层级都没了；照文本抄，就会删掉引导语（“筛选前使用下列治疗：”）、把子项并成一大段或提成独立条目，幻灯的“第 5 条”和方案的第 5 条不再是同一条。入排标准用 `tools/protocol_lists.py <方案.docx> --from 排除标准 --key exclusion` 直接取数据：第 n 条就是方案第 n 条，带子项的条款写成 `{"text": 引导语, "items": [子项…]}`，子项挂在引导语下，跟着方案编号；手写的（1）（2）也算子项。引导语不单独落在栏底，至少带上第一个子项。方案只有 PDF 时，编号照 PDF 印出的编号核对，并在交付里说明。

**核对两段链路。** 模板回执（`tools/kz_layout.py`）核对“数据 → 页面”：数据里的每条源文字都已上页。条款类数据还要核对“原文 → 数据”：渲染时加 `--source <方案.docx>`（或方案文本），每条都必须在方案原文里逐字找得到（忽略空格与全半角），否则命令退出 1；给的是 .docx 时，入排标准还核对编号与子项层级，与方案不符也退出 1。超长的单条标准在自己的分号、句号处接到下一栏，后段不带编号，也不写“续”。`tools/check_kz_project.py` 对没加 `--source` 的入排标准与 SoA、编号层级与方案不符的入排标准报错；只对文本核对过的入排标准（RULE-NUMBERING）、标题像条款内容却没核对的页、以及“概览/要点”式的条款页报警告。
