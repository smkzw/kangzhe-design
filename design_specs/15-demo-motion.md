# 15 演示性动画

本章拥有演示舞台：页面用来讲清方法、规则、计算、数据或计划的示范动画，包括何时必须做、可用形式、密度与幅度、内容依据、构图预设、PPTX 降级、视觉词汇与正反例。时钟、scene 步进、生命周期与减少动态归 06（FILM-05、MOTION-09）；数值图的语义、配色与空值归 05；字号归 03；禁止的动作仍按 06 MOTION-06。

## 何时必须做演示 DEMO-01
演示和装饰性动效的区别在于内容：演示用页面本身的内容，一步一步把“怎么做、怎么算、怎么判、数据说明什么、计划怎么走”做给观众看。卡片轮流出现、卡片之间描一条线、整卡平移、数字从 0 计数，单独出现时都只算入场编排（06 MOTION-04），不算演示。

- **HTML-PPT**：
  - 页面职责是方法、流程、规则、判定、计算、数据解读、计划推演、版本对比、风险评估、数据流转之一时，MUST 用演示舞台承载，不能只用卡片组加连线。
  - 每个讲方法或数据的章节 MUST 至少有一页演示；材料里有流程、计划或数据表时，先找能演示的页，再决定哪些页做静态卡。
  - 讲流程、规则、判定的演示 MUST 同时演示正例与反例（DEMO-09）。
- **站点与流式**：首屏电影（06 FILM-01）之外，讲方法与数据的段落 SHOULD 用演示舞台代替静态卡组。舞台在循环模式下运行。
- **不用演示的页面**：
  - 封面、目录、章节、尾页（11）；
  - 原文表、参考文献、纯结论页；
  - 材料里没有可示范的步骤、规则或数据的页面。不为凑动画编造示例。
- 交付计划（page-plan）在演示页写 `demo: {kind, preset}`，即形式（DEMO-02）与构图预设（DEMO-05）；方法或数据页不做演示时写 `demo: {none: "理由"}`。

## 形式目录 DEMO-02
先按页面职责选形式，不按观感选。一页只放一个舞台。

| 形式 `kind` | 适合 | scene 骨架 |
|---|---|---|
| `units` 单位流动 | 计数、清点、入组与脱落、资料或样本去向 | 一条记录一个方块：散点 → 按组归位 → 按状态着色 → 放大缺口 → 移入去向清单 |
| `calc` 计算演示 | 剂量换算、窗口期推算、样本量、合计与差额 | 原表 → 数值从原格飞入算式逐项相加 → 相减得结果 → 逐行核对回原表 |
| `story` 数据动画图 | 结果解读、亚组差异、构成与总量 | 同一刻度上逐幕换编码：柱 → 叠加 → 差额标出 → 按差额重排 → 堆成总量 |
| `timeline` 时间轴推演 | 项目计划、访视日程、给药周期、里程碑 | 指针逐季推进，任务条随之延伸，完成时打勾，最后标出里程碑季度 |
| `decision` 判定走查 | 入排判定、SAE 上报、偏离处理、核对规则 | 画出规则路径 → 示例个案逐个沿各自分支走到结果 → 结果计数 |
| `compare` 版本对比 | 方案修订、说明书更新、两种做法 | 两版并排（各自顺序）→ 按条目对齐 → 一致条目锁定 → 差异移入清单，并列两版取值 |
| `flow` 流程正反例 | 资料入库、SAE 上报、偏离处理、审批链 | 环节与规则 → 正例一次通过 → 简单反例退回返工 → 复杂反例反复不合格后升级 → 各环节问题计数 |
| `gantt` 甘特推进 | 项目计划、核对计划、注册与上市节点 | 计划与依赖 → 当前进度 → 一项延误沿依赖顺延、里程碑推迟 → 关键路径 → 追赶方案 |
| `swimlane` 跨部门泳道 | 问题单流转、跨部门审批、交接时限 | 各部门泳道 → 个案逐段交接、累计用时 → 超时环节标出 → 合计与时限比较 |
| `consort` 受试者流 | 筛选、排除、随机化、脱落、进入分析 | 筛选人群（一点代表 `per` 例）→ 排除并列原因 → 分组 → 脱落 → 进入分析 |
| `curve` 曲线解读 | 依从率、达标率、趋势比较 | 一条曲线 → 对照曲线同一刻度 → 目标线与达标时点 → 窗口差值 → 事件标注 |
| `breakdown` 构成拆解 | 总量构成、缺口来源、费用结构 | 总量 → 各部分占比 → 聚焦一部分 → 拆出子项 → 放回总量看占比 |
| `audit` 逐项核查 | 源文件核查、CRF 核对、清单验收 | 文档字段逐组核对（放大镜扫过）→ 不符项带规则复制到发现清单 → 相符率 |
| `matrix` 风险矩阵 | 风险评估、优先级排序 | 矩阵与高风险阈值 → 各项落位 → 高风险区计数 → 措施后移位 → 措施前后比较 |
| `network` 数据流转 | 系统接口、数据传递、样本与文件流转 | 各方与通道 → 数据包逐份沿路径送达 → 一份在中断通道受阻 → 数据包台账汇总 |
| `schedule` 访视窗口 | 访视日程、给药窗口、随访依从 | 访视目标日与允许窗口 → 受试者逐个落点 → 超窗与缺访标出 → 汇总偏离 |

- 十六种形式由 `KZDemo.mount(root, kind, data)` 生成，数据结构见 `runtime/API.md`；`examples/motion/` 是逐形式的图库，`examples/motion/deck/` 是 HTML-PPT 模板组（DEMO-07）。
- 每种形式只规定骨架，元素与文字全部来自传入的数据：环节数、任务数、泳道、矩阵档位、节点与路径都随数据变化，说明句由数据算出。
- 材料需要其他形式时（机制示意、剂量曲线、随机化分配等），用 `KZScenes.mount(root, spec)` 自定义对象与 scene，同样遵守本章各条。

## 密度与幅度 DEMO-03
推荐高密度、多 scene、大幅度、多维度推进的演示：每个 scene 推进一个维度（时间、状态、数量、位置、关系），不只轮流点亮卡片。门槛在 `motion.scenes.density`，用 `Stage.audit()` 与 `Stage.coverage()` 的回执核对：

- **规模**：至少 `min_scenes` 个 scene（含起始 scene），舞台上至少 `min_objects` 个持久对象。
- **每次转场**：至少 `min_changed_per_scene` 个对象改变。
- **幅度**：至少 `min_large_scenes` 次转场是大幅度的，即对象位移不小于画布的 `large_travel`，或面积变化不小于 `large_grow` 倍。
- **空间**：最满的 scene 里，可见对象触及的画布网格（`coverage_grid` 列×行）不少于 `min_canvas_coverage`；连线按笔画经过的格子计，不按外接框计。画布右侧或下方整块空着时，先放台账、清单、对照组或事实条，不放大字号或留白凑满。
- **图形**：舞台上至少 `min_figures` 个图形对象（图标、单位点、条、块、连线），不能只有文字框（DEMO-08）。
- **舞台占比**：HTML-PPT 演示页的舞台面积不少于幻灯片的 `min_stage_share`。
- **对象持久**：同一对象跨 scene 改变位置、尺寸、颜色、数值或文字，不在 scene 边界销毁重建。新对象从有意义的位置进入（`from`），例如从原表格子飞出、从上一个节点出发。
- **一个 scene 讲一件事**：每个 scene 配一句说明，最多两行，在底栏显示。同一 scene 内的对象按 `motion.scenes.stagger_ms` 错峰，总错峰不超过 `stagger_max_ms`。
- **幅度不靠加速**：运动时长固定为 `motion.scenes.move_ms`。信息太多时拆 scene，不调快动画。

## 内容依据 DEMO-04
- **数字**：舞台上的数字、计数、刻度、判定结果和说明句都由传入的数据计算生成，不手写进 scene。终值等于真值。
- **示例标注**：数据来自材料，或明确标为合成示例：在底栏标签写明（`note`），个案写“示例 A/B/C”，不冒充真实病例或真实结果。
- **不越出材料**：判定路径、步骤、版本条目只用材料写明的内容；不推断因果，不补材料没有的分支。版本对比的一致与差异由两版取值比较得出。
- **数据动画图**：全程同一刻度，空值不当 0，颜色跟随实体，类别色序固定（05 CHART-02/03）。
- **台账**：每个舞台附一份 scene 台账，逐项列出 scene → 对象 → 源字段 → 计算 → 说明句。骨架可以从 `audit().transitions` 导出，随交付计划提交。

## 构图预设 DEMO-05
- **HTML-PPT**：四个预设（13 BODY-01），阅读部分内容完整且静止，不随 scene 变化；舞台撑满所给区域，按 scene 步进（06 MOTION-09）。
  | 预设 | 构图 | 适合 |
  |---|---|---|
  | `demo` | 左 4 栏阅读卡，右 7 栏舞台 | 结论需要先读的页 |
  | `demo-mirror` | 左 7 栏舞台，右 4 栏阅读卡 | 从左读起的舞台：流程、网络、计划 |
  | `demo-wide` | 上方一行观点句与要点，舞台通栏 | 横向展开的甘特、曲线、泳道、日程 |
  | `demo-stack` | 舞台在上，下方事实条 | 舞台信息量足，结论是几个数字（`KZDemo.renderFacts(el, stage)` 用形式算出的 `stage.facts`） |
  - 相邻的演示页 MUST NOT 重复同一预设；一份讲稿里演示页多于三页时，四个预设都应出现。`tools/qc_plan.py` 检查相邻重复（DEMO-PRESET-REPEAT）。
- **站点**：用 `.kz-demo-split`（5:7，`data-side="left"` 时左右对调），舞台循环播放。
- **舞台结构**：
  - 画布在上，底栏在下；底栏放说明句、合成示例标签与 scene 状态条，标签不压画布；
  - 状态条的当前、已过、未到三态按 06 的状态可辨要求区分。
- **字号**：
  - 舞台标签、计数、表体用 secondary 或正文角色（03 TYPE-01）；
  - 节点标签随画布宽度在 secondary 与正文之间取值，同一舞台一致，不低于 secondary。
- **验收视口**：每个 scene 的文字对象都不重叠、不出界、不溢出。

## PPTX 降级 DEMO-06
PPTX 没有可 seek 的时钟。演示降级为一组连续页，每个 scene 一页：
- 持久对象在相邻页用同名 Morph 配对（06 MOTION-07 的 `morph.pairs`）；
- 数字与说明逐页写成原生文本；
- 增加的页数写进交付计划。

本包的 PPTX 参考实现尚未覆盖这一降级。首次使用时按 10 G9 在 PowerPoint 实机验收 Morph；不支持 Morph 的客户端回退为淡入淡出。

## 视觉词汇 DEMO-08
演示舞台用图形讲内容，文字只做标注。
- **元素**：
  - 线性图标（`KZIcons`，文档、人员、中心、实验室、日历、数据库、签字、归档、警示等）标出“是什么”；
  - 单位点、条、块、热区、泳道、连线、途经点轨迹标出“有多少、在哪里、怎么走”；
  - 状态用同一对象换样式表达：通过、失败、高亮、延误、顺延、关键路径、恢复，不另画一个对象。
- **图标的边界**：图标只代表材料里写到的实体（资料、受试者、中心、系统、访视）；不画机制示意、解剖图或研究结果的象征图（04 不编造机制图）。图标为本包绘制，不引入第三方图稿。
- **文字对象**：标签、计数、说明用 03 的角色字号；多行标签自动均衡换行，不留孤字；卡片式文字框不超过舞台对象的一半。
- **反模式**：左卡右动画千篇一律、只有卡片加文字、舞台一半空白、对象轮流淡入淡出而不移动。这些都按 DEMO-03 与 DEMO-05 的门槛判不通过。

## 正例与反例 DEMO-09
讲流程、规则、判定、核查的演示，MUST 让观众看到“对的样子”和“错在哪里”：
- **至少三个个案**：一个正例（一次通过）、一个简单反例（一处不合格，退回后通过，或在第一道判定就分流）、一个复杂反例（过了前面的环节、在后面的环节失败，或多处、反复不合格，最终升级、受阻或偏离）。`flow`、`decision`、`audit`、`network`、`schedule` 的示例数据都按这个结构准备：例如判定走查里“已收到但差异未确认”的个案、数据流里过了第一跳才受阻的数据包、访视里多次超窗加缺访的受试者。
- **反例的路径看得见**：返工走回到哪一环、在哪条通道受阻、哪次访视超窗，都画在舞台上，并计入环节问题数或台账。
- **汇总 scene**：最后一个 scene 给出正例、返工、升级（或受阻、偏离）的计数，以及问题最集中的环节，数字由个案算出。
- 计划类演示（`gantt`、`timeline`）同理：先演示按计划推进，再演示一项延误怎样沿依赖传导，最后演示追赶方案的效果。
