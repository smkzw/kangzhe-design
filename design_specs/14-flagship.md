# 14 旗舰路线（对外与顶层汇报）

HTML-PPT 与 PPTX 各有两条路线：**常规**（01–13 的现行规范）和**旗舰**（本章）。旗舰用于对外汇报和向公司顶层领导汇报：浅色画布上铺一张流动的全屏光场，配液态玻璃透镜，翻页时由光完成转场；内容页的光退到页边，阅读面保持安静。数值只在 `tokens.flagship`。

## FLAG-01 选路阻断与判定（MUST）
用户要求做 HTML-PPT 或 PPTX 时，Agent 必须停下，请用户在“常规”和“旗舰”之间选一条路线。得到明确答复之前，不做计划、不生图、不搭脚手架、不导出，即使用户已经上传了全部材料。

提问之前，先根据用户上传的材料和提供的信息做出判定，给出推荐路线和两三条具体理由，再请用户确认或改选。判据如下：

| 信号 | 指向旗舰 | 指向常规 |
|---|---|---|
| 听众 | 外部：合作方、KOL、投资者、会议听众；公司顶层领导、管理层、董事会 | 部门内部、跨部门例会、项目组 |
| 场合 | 大会、发布、战略或年度、季度管理层汇报、重要拜访 | 周会、进度同步、培训、工作记录 |
| 材料 | 结论导向，页数少，少数几个关键数字承担论点 | 页数多、表格密集、以过程和明细为主 |
| 用户措辞 | “对外”“给老板”“高规格”“惊艳”“高大上”“发布” | “日常”“内部”“简单”“快速”“照模板” |
| 放映与分发 | 用 Edge/Chrome 放映，现场讲述 | 主要打印或以文件分发阅读，或放映环境不是 Chromium |

两边信号都有时，以听众和场合为准；放映环境只能是非 Chromium 浏览器时，推荐常规，或说明旗舰在该环境下降级为磨砂玻璃（FLAG-09）。

提问的格式是一句判定加一个选择，例如：“推荐旗舰：这是给集团管理层的季度汇报，结论集中在 3 个数字上，并且会用 Edge 放映。请选择：常规 / 旗舰。”宿主有提问工具时用提问工具；没有时输出这个问题，停在这一步等待答复。

用户在本次请求里已经明确指定了路线（如“用旗舰版做”），视为已经选择：复述一句并继续，不再追问。修改一份已有的 deck 时沿用它原来的路线（HTML 看 `body.kzf`，page-plan 看 `route`），不再阻断；用户要求换路线时才重新选。用户要求的轨道是站点式或流式 HTML 时，不触发本阻断。

## FLAG-02 与常规规范的关系
旗舰沿用以下规范，不另起一套：品牌色、部门色与官方 Logo（01 CORE-01/02/05）、字号下限与中文表达（03）、数据真实可编辑与图表规则（05）、讲稿（09）、下钻与甘特（07、08）、门表（10）、验收视口（13 FOLD-04）。

以下条文在旗舰中由本章替代：

| 常规条文 | 旗舰的做法 |
|---|---|
| 01 CORE-04 正文页固定 chrome（双菱形、标题横线、页脚两槽） | 不用固定页眉页脚，由身份胶囊锚定部门（FLAG-06）；正文页不放双菱形（02 LG-03 只适用于常规） |
| 02 LG-01 同族玻璃卡承载正文 | 正文放在不透明纸卡上；液态玻璃只用于框架元素（FLAG-05） |
| 04 IMG-01/05 每页映射真实生成图 | 背景由品牌光场生成（HTML 为实时着色器，PPTX 为 `tools/flagship_plate.py` 渲染的光效图），在资产清单登记渲染参数与哈希；不需要 AI 生图 |
| 06 MOTION-04/08 卡片波浪入场、翻页瞬时切换 | 光先转场，光停下后内容入场（FLAG-04） |
| 11 hero 固定版式 | 旗舰 hero 构图（FLAG-07） |
| 03 TYPE-01 角色字号（页标题、卡标题、hero 角色） | `flagship.type_px`；03 的字号下限、同页同角色同字号与孤字规则照常 |
| 10 G2 的 `qc_plan.py` 证据 | page-plan 写 `"route": "flagship"`，hero 页 `hero_layout_id` 为 `flagship-<kind>`，背景 `image.mode` 为 `flagship_light_field`（PPTX 附 `plate` 回执）；qc_plan 据此改用旗舰字号与光场检查 |
| `brand_budget` 饱和暖色 ≤12% | hero 页不设上限，内容页仍要求浅色像素 ≥80%（FLAG-03） |

06 MOTION-06 的禁止项在旗舰中照样有效。旗舰只放开四项：全屏光场、光转场、透镜折射、身份胶囊位移。

## FLAG-03 浅色画布与页面角色光量
- 画布是 `flagship.canvas`，不做深色舞台。
- 光量按页面角色分三级（`flagship.levels.by_kind`）：
  - **3 级（封面、目录、尾页）**：光河与光雾全量。
  - **2 级（章节）**：光河从数字下方穿过。
  - **1 级（内容页）**：光退让。
- 内容页的退让：
  - 标有 `data-kzf-calm` 的阅读区（纸卡、标题、说明）以羽化矩形挡住光场，背后保持安静的画布色。
  - 光只留在页边，并在光河压成的底边地平线上。
  - 唯一的聚光对象（`data-kzf-pool`，通常是关键数字的透镜）背后保留一池光，让光等于重点。
  - 每页最多一个聚光对象。
- 光的走向随页面焦点（`data-kzf-focus`）变化；光河路径取 `flagship.river` 的页型值。
- 验收：内容页去掉文字后，阅读区内的光场亮度与画布色之差不超过可见阈值，并且整页浅色像素 ≥80%。

## FLAG-04 光场与转场
- **光场**：一张全屏 canvas 垫在所有页面之下，所有页共用，不按页新建。画面由时间、翻页进度和页面几何决定，可以定格到任意一帧（QC 用 `?kzf-t=秒`、`?kzf-p=进度`）。不使用积分状态、粒子或流体模拟。环境光的流速取 `flagship.field.speed`，低频画面按 `render_scale` 渲染并加抖动，避免色带。
- **转场**：
  - 翻页时，一道暖色光波横扫全页，光的焦点和光河从上一页移到下一页，时长 `transition.duration_ms`；离场内容在 `exit_ms` 内淡出。
  - 新页内容在光停下（`content_delay_ms`）后入场：文字带轻微模糊上移，玻璃从微缩放落定，错峰 `step_ms`。
  - 同一时刻只有一个主光在动。
  - 连续快速翻页时，整页光波的间隔不短于 `min_interval_ms`，避免构成闪烁（WCAG 2.3.1）。
- **静止与降级**：
  - 系统“减少动态”打开时，光场只画一帧，转场取消，内容直接显示。
  - 打印与上游 `?preview` 显示终态。
  - 页面不可见时光场暂停。

## FLAG-05 液态玻璃透镜
- **材料**：
  - 透镜在 Chromium 上用 SVG 位移作 `backdrop-filter`：圆角矩形的距离场生成位移图，只在边缘环带折射，中心为零，所以透镜里的文字不变形。
  - 承载文字的透镜是半透磨砂玻璃，不是全透玻璃。边缘环带保留折射。中间阅读区按 `flagship.lens.roles` 第三项磨砂，再降饱和（`flagship.lens.frost_saturate`）并提亮（`flagship.lens.frost_lift`），背后的鎏金只剩淡蜜色；玻璃面约一半白（`flagship.glass.face`）。章节号上的透镜不承载文字，用 `flagship.glass.face_clear` 保持通透。
  - 边缘有随光向转动的 conic 高光环，底边有焦散反光。
  - 参数取 `flagship.lens.roles`。
  - 其他浏览器退回磨砂（`fallback_blur_px`）。
- **用途**：透镜只用于框架元素，即身份胶囊、关键数字、hero 数据条、章节号、决定事项卡。每页最多 `lens.max_per_page` 块（身份胶囊不计）。
- **不放透镜的位置**：图表、表格、甘特和正文段落后面不放透镜；不做玻璃叠玻璃。
- **backdrop root**：透镜元素的祖先不能有 filter、opacity<1、mask、clip-path、backdrop-filter、非 normal 的 mix-blend-mode、`view-transition-name`，也不能有对应的 will-change；这些都会形成 backdrop root，让折射采样到空白（扩展 02 LG-04）。入场的透明度和模糊写在元素自身。

## FLAG-06 身份锚（不用固定页眉页脚）
- **身份胶囊**：每页都有一枚液态玻璃身份胶囊，内含官方 Logo 原件和部门名（`flagship.identity.name`）。它是整套 deck 唯一持续存在的对象，翻页时滑到该页型的角落锚点（`identity.anchors`，边距 `identity.margin`），位置变化随光转场完成。
- **胶囊的限制**：不写页码和日期，不改 Logo 颜色。
- **日期与场合**：封面和尾页的元信息行写日期与场合。正文页不写页脚。
- **页码**：需要页码时，由上游演讲者窗口提供，不画在观众页上。

## FLAG-07 版式与 hero 构图
**排印**
- 标题用中等字重；关键数字用超细字重（`flagship.numeral_weight`）、超大字号。
- 分隔用发丝线（`flagship.rule`）。
- 引导语前加一段短横线。
- 强调沿用 03：数字风险用深红，要点加粗。
- 字号取 `flagship.type_px`，不低于 03 的下限。

**hero 构图**（固定形态，宽屏时向两侧铺满，不居中留边）
- **封面**：左上是引导语、两行标题和一句引言；下部是一条横贯全宽的玻璃数据条，承载 2–4 个关键数字。数字必须来自材料；没有关键数字时，这条换成场合信息，不编造数字。
- **目录**：章节编号用超细大号数字，每个章节一张玻璃卡；不超过 4 章。
- **章节**：左侧是超细巨号章节数字，上面压一枚透镜（数字在透镜里弯折）；右侧是章节名和一句引导。
- **尾页**：标题居中，下面是决定事项或行动的玻璃卡，至多 3 张。

## FLAG-08 内容页
- **构图**：
  - 页标题左上，下面一条发丝线。
  - 阅读面放在白纸卡（`flagship.paper`）上：图表、表格、甘特、正文都用纸卡，不用磨砂。
  - 右栏至多一枚关键数字透镜（同时是聚光对象），下面可以有一段说明，以粗线开头。
- **光量**：内容页光量为 1 级（FLAG-03），纸卡、标题和说明都要标 `data-kzf-calm`。
- **密度**：沿用 13 BODY-01 的跨度与 03 的字号；放不下就拆页，不缩字。
- **组件**：图表用 ECharts（05）；甘特、下钻沿用 07、08 的组件，放在纸卡里。

## FLAG-09 HTML-PPT 旗舰
- **起点**：仍从 html-ppt-skill 脚手架起步，接入方式同 `adapters/html-ppt.md`：单位、生命周期，不另做放映器。
- **加载**：品牌层多加载 `runtime/kz-flagship.css` 与 `runtime/kz-flagship.js`，`body` 加类 `kzf`。
- **装配**：用 `KZFlagship.mount(deck)`，光场、透镜、身份胶囊、转场都由它负责（接口见 runtime/API.md）。
- **页型与光量标记**：页型写 `data-kzf-kind`（cover / toc / section / content / ending）；焦点写 `data-kzf-focus="x,y"`（视口比例）；阅读区标 `data-kzf-calm`；聚光对象标 `data-kzf-pool`；透镜用 `.kzf-lens[data-kzf-lens=<role>]`。
- **放映环境**：Microsoft Edge 或 Chrome（Chromium）。其他浏览器中透镜退回磨砂，光场照常；交付说明要写明这一点。
- **WebGL 不可用**：显示 CSS 渐变光场，这一降级要写进 G9。
- 参考实现：`examples/reference/htmlppt-flagship/`。

## FLAG-10 PPTX 旗舰配套
- **路线**：PowerPoint 没有实时光场。旗舰 PPTX 用静态光效图加原生对象表达同一套视觉，仍经 ppt-master（`tracks-pptx.md` 与 `adapters/ppt-master.md`）。
- **背景**：每页的光效图由 `tools/flagship_plate.py` 按页型、焦点、光河和安静区渲染（`flagship.plate`），作为整页背景图。内容页渲染时传入阅读区矩形，光效图上阅读区已经安静。在资产清单中登记渲染参数与 SHA-256。
- **玻璃**：PowerPoint 不能模糊或折射形状背后的内容，所以每块玻璃分两层：
  - 下层是一张预先烘焙的透镜图片。`flagship_plate.lens()` 从同页光效图裁出玻璃范围，按 FLAG-05 同一组参数，在阅读区磨砂、降饱和、提亮，在边缘环带折射；形状外透明。
  - 上层是原生玻璃壳：`flagship.glass.face` 渐变面、白色细边和单个外阴影（02 LG-PPTX 的做法）。
  - 两层都是可选中的原生对象。移动卡片时两层一起移动，否则透镜图会和背景错位。交付说明写明“静态近似”。
  - 章节号透镜放在数字下层，数字不弯折，透过 `face_clear` 显示。
- **身份胶囊**：用原生圆角矩形，内放官方 Logo PNG 和部门名，位置取同一组锚点。
- **动效**：沿用 06 MOTION-07（淡入、错峰 `pptx_card`、图表擦入）；页面转场用淡入淡出，不模拟光波。
- **验收**：同常规 PPTX，包括检查器、交付检查、OOXML 回读，以及 PowerPoint 编辑保存回读。
- 参考实现：`examples/reference/pptx-flagship/`。

## FLAG-11 验收增补
在 10 的门表中按下列内容填写：
- **G0**：写明所选路线和 FLAG-01 的判定理由。
- **G2**：`qc_plan.py` 在 `route: flagship` 的 page-plan 上无错误（PPTX 用 `--asset-root` 核对光效图哈希）。
- **G1**：身份胶囊每页可见；Logo 哈希一致；正文页没有固定页眉页脚。
- **G5**：
  - 透镜可见折射，或已写明降级；
  - 承载文字的玻璃阅读区是半透磨砂（PPTX 为烘焙透镜图），背后的光不与文字争抢；
  - 每页透镜数不超过上限；
  - 内容页阅读区安静，浅色像素 ≥80%；
  - 宽屏铺满。
- **G7**：光转场与内容入场的先后顺序；光场在 `?kzf-t` 下可定格；减少动态只显示一帧；连续翻页光波间隔 ≥ `min_interval_ms`；后台暂停。
- **G9**：在 Edge 或 Chrome 中逐页放映；非 Chromium 降级截图；PPTX 在 PowerPoint 中回读。
