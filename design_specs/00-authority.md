# 00 规则归属与使用边界

## 单一权威
本包只有 `kangzhe-design 6.0.0` 一个技能入口。旧 flat、3d 名称仅用于识别用户意图，不对应运行模式。不保留任何存量卡片色条豁免；不得将旧文件复制回来以解决新规范的空白。

决策顺序：本次用户明确约束与事实真实性 → 本文件的能力/权威边界 → 对应主题的规范所有者 → 轨道适配 → 示例。**实现代码和示例不是高于规范的权威**。布局数值常量由 `tokens/tokens.json` 唯一持有；原始 Logo 与仅限 PPTX/HTML-PPT 的用户锁定双菱形资产保留各自原生几何/材质数值，tokens 只登记资产路径和 hash，不再另存近似形状；文档中的解释不能暗改它。修改数值时修改 token、重新生成派生产物、运行回归。发现代码和规范不一致，修代码或正式修规范，禁止“以实测代码为准”自行生效。

机械执行约束属于上游引擎。例如 PPT Master 原生图 schema、导出流程和 HTML-PPT 导航 API 均不得由本包重新定义。上游通用审美默认值可由康哲视觉参数覆盖；上游真实能力上限不可用视觉要求强行越过。无法兼容时阻断对应能力，不阻断已证实可行的其余工作。

## 适用场景
用于正式医学、研发、管理汇报以及相应信息站点。不是年轻化品牌宣传模板。视觉可现代、有空间感和有目的的动态，语言仍专业克制。除业务材料本身有要求，不在设计技能里强制某个 AI 产品定位、某项临床方案章节顺序或“只能辅助不能决策”等特定项目结论。

## 规范的强度
MUST/禁止是可定位失败的硬要求；SHOULD 是需要理由的默认选择；实验阈值是校准起点，须记录测试，不冒充科学定律。风格评分不能覆盖事实错误、字号失守、裁切、无图冒充生图、假可编辑或后台静态保护失效等硬失败。

## 状态与交付
`implemented`、`tested_local`、`tested_peer`、`tested_target_office`、`pending` 分开记录。`review` 和 `agent` 是重构维护资料，不是未来汇报的受众内容。禁止把制作日志、失败分析、内部文件路径写进汇报正文。制作时可将审计记录留在独立工作目录；公开交付包默认不夹带内部原材料。
