# 05 四轨统一图表语言

## 语义数据先于图形
建立 canonical chart data：稳定的 chart/series/point id、类别/时间、数值、单位、缺失值、估计量、分析人群、时间点、区间类型、必要限定。同一数据对象派生 HTML 与 PPTX，不手抄两份数。严禁把 null 转成 0、把描述性趋势写成推断结论、用样本不同的比例混充直接比较。

HTML-PPT、站点、流式中的数值图都由随包 ECharts 构造；流程示意、机制示意不编码精确数值时可用 SVG/DOM。生成图不能画统计结果。部门色只在确实表达部门时使用；治疗组/对照组的映射必须全篇稳定，不随页面换色。

## 共同形态
柱/条：平直、准确的量值轴，轻微端部圆角，颜色与淡渐变来自同一调色板；不做透视立柱、立体厚度、夸张玻璃高光扭曲高度。负值按同一系列颜色展示，不能误染成风险红。比较量值通常保留零基线；特殊截轴须明确说明。

普通时间折线：默认有 **线下低透明度浅面积**，沿量值零轴填充；线仍是主要读取对象。默认 `smooth:false`、`connectNulls:false`，显示真实点位和缺口。面积只是视觉辅助，不能解释为累计量或置信区间。多系列严重遮挡、真正 CI band、KM/森林/散点等情形不得盲目套线下面积；在图表计划记录理由，选择科学上正确的表现。**ECharts 不要求折线一定有面积，这是本品牌的默认视觉规则**。

误差线/置信区间使用真实 `low/high` 和明确统计名称；不得把不同概念混成“误差范围”。图例、轴单位、人群、时间点在必要时可见，不挤进 tooltip 才能理解。去掉来源备注不意味着删除估计量或研究设计限制。

## HTML 实现
`runtime/kz-charts.js` 提供基础柱/折线选项、缺失值校验、进度驱动和生命周期；`assets/vendor/echarts.min.js` 为原包自带并校验的 6.1.0。复杂森林图、CI、热图、流程相关 Sankey 等用官方 series/custom 能力，仍继承同一数据和材料规则。**基础工厂不等于全部统计图已实现**；额外图型须按任务加实现和测试。

图表壳采用同族玻璃，绘图区是稳定阅读面。禁 tilt 坐标面。挂载后尺寸改变要 resize，drawer 隐藏时不以零尺寸初始化；打开后再 resize，关闭时 dispose/暂停按状态策略执行。图例切换不重排颜色；数字格式不得忽然丢掉规定小数。

数值增长动画须由同一个 normalized progress 驱动柱/折线显露和数值更新；单位、样本量与最终值在静态数据模型中先存在。用户正在读取/编辑或 reduced-motion 时立刻呈现真值，不重复从零增长。没有到达页面的图表不得持续消耗帧。图表可下钻，但 tooltip 不是下钻页面。

## PPT Master 原生对应
截至所审阅上游，原生 `line + area` 应通过 `combo` 中共享数据的 area 与 line 映射，不是给它传一个 ECharts `areaStyle`。源 SVG fallback 与元数据同改、同步、hash stamp，再按官方原生图表导出门激活。最终须核对图表数据与嵌入工作簿，不能仅看到柱形就声称是原生图表。

原生图可能无法逐像素复现浏览器渐变和交互，验收重点是相同配色/字号/轴口径/数据/层级与足够接近的材料外壳；不追求以截图换取完全相同。PPT Master 当前原生 chart schema 不支持 gantt；甘特采用原生形状+可编辑标签，由官方引擎输出。此事实不能通过写一个 `type:gantt` 字段改变。

## 双轨验证
用一份数据输出相同柱/折线，在 HTML 与 PPTX 导出前后逐值比对，关注顺序、零值、负值、null、极值、四舍五入、单位和 legend。低层度 CSS 图形不是 ECharts 合规实现；ECharts 渲染出的 PNG 也不是可编辑 PPTX 原生数据图。
