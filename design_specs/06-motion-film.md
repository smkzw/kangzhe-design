# 06 动画电影与连续形变规范

本章是四轨动态语言的唯一所有者。HTML-PPT 保留上游翻页控制；站点与流式保留自然滚动。电影是页面内解释信息的有序时间轴，不是自动翻页，也不是一组互不相关的入场动画。

## 1. 什么才算动画电影 FILM-01
必须同时具备：有材料依据的叙事问题；至少三个有关联的状态；可识别且持续存在的主载体；有顺序的建立、解释、关系变化和收束；自动推进且无观众播放器控件；后台生命周期可暂停/定位；首尾能够无跳切地接续；静态完整信息仍可访问。

不算：只有背景粒子、几张卡轮流 fade-in、滚轮不动就永不推进、录好的一段视频、从一页截图 crossfade 到另一页截图。CSS 能做漂亮效果，但“漂亮动效”与“说明信息的电影”是不同验收项。

**站点首页和每个独立章节页首屏必须有电影。流式文档首页和一级章节入口提供相应章节电影。** 不要求每个小标题、每张卡也循环；避免浏览长文时到处同时运动。HTML-PPT 的封面/章节/流程/关系页优先采用电影，密集原文表、统计明细页采用稳定的分组入场即可，不强迫每页都拍一部电影。

## 2. 先写电影设计书，后写动画代码
每部电影单独一份 `film-plan.json`，至少有：
- `id / page_id / question / audience_message`：要解释什么，不写纯审美目标。
- `source_claim_ids`：每个业务结论的私有材料定位；合成示例则明确 synthetic。
- `carrier_id`：贯穿全片的唯一主要元素 ID；有多个独立叙事对象时各自有稳定 ID。
- `protected_regions`：标题、Logo、导航、文案、控件、数据区及其运动扫掠范围。
- `states`：各关键时刻的几何、圆角、材质色、文案、数据和解释任务。
- `relations`：连接谁、何时建立、意味着什么；无依据的因果关系不能画成因果箭头。
- `timing`：各段进入、理解、停留、交接；各段真实秒数与总时长。
- `loop_contract / static_summary / lifecycle_api / audience_playback_ui=false / reduced_motion / cleanup`。

禁止先做一段酷炫动画再把文字塞进去。每个状态都要回答“观众此时看懂了什么，新状态为何由上一状态发展而来”。没有新增解释价值的段落删除。

含数量、状态或字段的电影，在计划旁保留简短的数据对账表：画面对象 → 源字段/范围 → 单位 → 计算 → 受众标签。示例：三组“版本比较结果”的已核对字段为2/3/2，合计7，只能标“比较结果：已核对7个字段”，不能挂到“v1登记页”变成v1数量。条目数与字段数、单版本状态与两版本比较结果分别核对；数值恰好相等不代表口径相同。仅某组具有的字段不能写成所有组共同字段；材料未给逐条目到字段的对应关系时不得画出确定映射。核对用私有源定位，不增加受众页内部资料引用。

## 3. 一形不切 FILM-02
“一形不切”约束 **叙事载体的身份连续**，不表示整个网页只能有一个 DOM 元素。一个原有卡/圆片变成宽面板时，保持同一个 DOM 节点或同一个可追踪 SVG path；改变它的位置、尺寸、圆角、色彩、光学参数。不得隐藏原卡后创建一张新大卡，用交叉淡入冒充同元素形变。

禁止行为：主载体 opacity 归零再换物体；在时间边界 destroy/create；React 更换 key 导致重新挂载；从 SVG 载体切到 DOM 复制品并声称同一元素；分裂为多球后任取一球叫原载体；用视图转场的前后截图宣称运行时 DOM 身份相同。

允许行为：持续存在的主面板展开后露出它本来容纳的子信息；预先存在的其他对象按顺序进入；用连线表达主载体和这些对象的关系；文案在稳定的文字槽中改换（文字不属于需保持同一像素内容的载体）。子节点的进入不应让主载体的外形出现切断或凭空换位。

使用 React 时把稳定 carrier 放在不会被条件分支替换的位置，以稳定 key 维护；动画库只更新它的属性。业务状态机可以改变内容，但不能把视觉连续性寄托于两个不同组件恰好相似。React 是可选实现，不要求给静态 HTML 项目新增 React 构建链。

## 4. 可复用的叙事语法
### 4.1 研究流程
一枚研究信息片 → 展宽成阶段容器 → 相关步骤与角色依次建立连接 → 聚合为完整流程 → 主载体收回起始形态。步骤来自材料，不加虚构环节。各节点形成后保留足够停留，禁止一闪而过。

### 4.2 证据组织
一项研究卡 → 同一载体展开成人群/方法/结果三个阅读区 → 结果图随共用进度显露 → 出现由证据支持的解释 → 结构收束回研究卡。研究结果不可从随机数字增长为最终值来暗示真实时间变化；仅短时视觉揭示。

### 4.3 部门协同
主载体代表同一任务；相关部门以固定身份色出现；信息或责任连接依序显露。任务载体经过状态变化仍是同一对象。部门色不是装饰流光，不在每个场景随意变色。不能把“AI 自动批准”等原材料未支持的行为画入流程。

### 4.4 信息结构展开
同一玻璃容器从概览扩展为分类面板，再以持续存在的分区展示明细，最后收拢。多层信息可下钻；电影先说明组织方式，细节放在下方及对话框，不把全部表格挤进首屏。

### 4.5 阶段计划
稳定时间轴上依序延伸任务条，数字/标签与条长共享进度；完成后稳定呈现。用户点击条后暂停电影进入编辑，不允许动画继续拉回用户刚修改的时间。

## 5. 时间设计 FILM-03
默认电影参考时长约 36 秒，不是所有页面固定 36 秒。通常 4–6 个主要状态；复杂关系可延长，单一概念可缩短。每段分配进入/建立/阅读停留/交接：参考 15% / 30% / 40% / 15%，**停留由文字和信息量决定**。关键说明建议至少 2 秒，并按中文约 5–7 字/秒加起读时间估算；这只是排片起点，需要实际观看校准。

文字稳定后才开始计算阅读停留。图表长出一半时不能把完整结论闪过。关键观点/关键限制不得只有短暂窗口；下方静态摘要必须能随时复核。片头不是漫长 logo 片头，首屏迅速给出主题与可理解状态。

相同动作采用一致的速度感：卡片进入约 0.44 秒，退出约 0.24 秒，顺序间隔约 70ms，数据揭示约 1 秒。具体值由 tokens 提供。流程按语义顺序，不按 DOM 随机顺序。超出观众阅读能力时减少同时变化对象，而不是把动画调快。

## 6. 首尾接续 FILM-04
必须明确起点和终点是同一叙事语境。最后一段通过可解释的回收/回到概览把载体带回第一状态，随后继续播放；不做黑帧、白闪、闪烁或瞬移复位。最后状态和首状态的 x/y/w/h/r/color/opacity 逐项相同；旋转、阴影、裁切和附属节点也须对齐。

位置与属性至少 C0 连续，速度在首尾宜接近零（用平滑缓入缓出或显式停留，达到 C1 接续）。不是只比较两张端点截图：要看最后 300ms + 最前 300ms 的视频/帧序列。主载体在接续时不可被偷偷隐藏。首尾几何之差按归一化坐标1e-4机器验证、渲染后像素差再复核；这是接续比较的工程容差，不是允许关键帧越出舞台的容差。输入边界按当前runtime/API的x+w/y+h约束核对，不替代肉眼。

如果业务叙事不适合回圈，必须设计“回到总览”的可解释尾段，而不是用无语义缩放倒带。系统减少动态、编辑或非活动层要求暂停时，循环不得自行恢复。

## 7. 控制模型与生命周期 FILM-05
观众页面不得出现“播放、暂停、继续动效、重播、开始播放下一页”、播放器进度条/滑杆、时间码或隐藏后hover唤出的控制面板。进入活动页或章节首屏后，动画自然自动推进；回接自动发生，普通翻页继续由上游导航控制，不自动跳页、不增加开始按钮。静态信息直接呈现或通过有业务含义的详情入口访问。声音默认无。此项依据用户A03明确修订，取代此前常驻播放器控制要求；后台生命周期接口不属于观众UI。

采用暂停原因集合，而非一个互相覆盖的布尔值：`user / hidden / offscreen / editing / modal / reduced-motion / engine-inactive / capture`。只有对应原因解除才恢复；用户暂停之后切后台再回来仍暂停。电影离开视口或 PPT 幻灯片不活动时停止 RAF；恢复不能因为累计后台时间跳过整段。

`seek(p)` 应直接得到完整一致的状态，包括形状、线条、数字和文案，不依赖先前播放路径。录屏/截图需要确定性，可设置 seed 并冻结指定进度。挂载、卸载和再次进入都不能重复注册监听器、重复初始化 ECharts、留下后台定时器。组件拥有 `pause/resume/seek/dispose`，每个属性只有一个动画 owner。

所有权须落实到实际被写入的元素：不同/嵌套根节点不得同时驱动同一 carrier、reveal 元素或 tilt 元素。公开 `reveal(root)` 也登记实际目标；入场完成释放，退场 forwards 保持期间需调用返回序列的 `cancel()` 后才能换驱动者。完整页面优先使用 `mountPage` 的 enter/leave/finish/dispose，不能在其已挂载目标上另调 reveal。重复挂载须在改属性/注册监听之前拒绝，先 dispose 才可重新挂载；不因 root 的 ID 不同允许第二时钟。初始化失败也释放已占用元素。互不共享动画目标的独立组件可并存。

禁止滚轮劫持、强制长距离滚完才能见内容、阻止用户下滑离开首屏。自然滚动不改变电影时钟；不向观众暴露进度拖动。站点页面之间的转场可保持设计连续，但不要声称不同文档共享同一个 DOM 元素。

## 8. 图层与文字保护 FILM-06
主载体从最小到最大尺寸的扫掠区域不能撞标题、Logo、导航、关键解释或图表。每个 keyframe 与中间插值都检查；只检开始/结束不够。字体与标签不能被透视、挤压或超过安全区。

参考 Film 的 `minCarrierWidth` 默认160个舞台CSS像素，可明确设为0保留计划几何；不得传负数或非有限值。最小宽度可能扩张载体并左移以留在舞台，`snapshot().geometry` 和 onRender 后的实际矩形须作为保护区检查输入，分别记录 requested/effective/stage/adjusted；不只检查原始关键帧。每档resize、静态态和正常插值均检查实际扫掠范围。dispose 后的 pause/resume/seek 为无作用调用，不改进度或暂停原因。

主文字在稳定的 reading zone，电影在清晰的 stage；需要内部文字时在面板展开到足够大之后显露，收回前先退出内部文字。不能把最终大面板文本缩成小圆点内的密字。数据绘图区保持平面；玻璃光斑在其外围，不从统计柱与数字上扫过。

若项目用业务状态表驱动文字，`KZMotion.Film` 可显式设置 `managedText:false`，由项目 `onRender` 作为唯一文字写入者；几何、时钟与生命周期仍由 Film 管理。默认保留关键帧文字管理。默认模式每个关键帧必须显式提供字符串 label/caption，空字符串只能用于策划明确的无字阶段；业务文字模式不由 Film 清空文字。不要同时让关键帧和业务回调反复覆写标题/说明，否则容量测量可能对应上一状态。更新当前状态文字后，才测量并决定显露时机；初始化、正常播放、RM 和打印均使用同一来源。

具体收束顺序：先在仍有足够容量的载体中完成阅读停留，子信息有序退出至不可见，再收小载体；不能从最大关键帧立即持续缩小，却到下一状态才隐藏内部文字。正常播放时对所有仍可见文字检查字形矩形，透明度衰减期间也不能越出阅读区。首屏及每个下钻电影分别验证，不能以首页通过代替子电影。

卡片外层负责布局，内层负责 hover tilt，再内层负责进入位移；不要让 CSS transform、JS transform 和动画库同时写同一元素 transform。优先分层或共享同一个合成函数。clip 用于物体外形，不能裁掉文字。

## 9. 宽屏与响应式构图
站点电影舞台一般占视口宽度至少 88%，整体外围留窄边距，不把所有内容塞进 1100px 中央柱。**文字行长不随之无限拉长**：阅读栏受控，电影、图表、关系图和多列卡片利用剩余宽度。横向信息在 ultrawide 可扩为多区域，不能把一张小卡放大成空箱。 同样不能把若干短标签逐行拉到全宽：宽度要对应实际关系分区，例如相邻版本列、并列清单组或输入/处理/结果区，而非同一句信息重复出现在载体和外部卡片。各区保留受控行长；如果信息不足以支撑当前宽高，缩小当前载体并用有依据的关联实体组成舞台，不凭空补业务内容。

电影内部采用归一化坐标或统一 viewBox；桌面 resize 后重新计算边界和保护区，不二次随意 scale 文字。站点式 HTML 只按 tracks-site 的桌面宽屏矩阵验收，不要求手机/窄屏版；其他轨道合同包含移动阅读时，可改为上下布局，保留语义顺序与稳定载体身份，使用低复杂度场景，不把整个宽屏按 0.2 倍缩小成不可读缩略图。站点正文不受 PPT 固定画布约束。

展开面板中的子卡和阅读组同样遵守03 TYPE-02。不能让网格flex:1/stretch把几个短标签变成巨高空壳。先按文字量确定子卡/阅读组的合理高度，再联合确定舞台和各状态的载体几何；收束态、中间插值和窄屏也重新核对容量，不为填高增加事实外文案。分对象测量、居中模式与独立审阅争议的验收按10 G5-NESTED执行。

## 10. 下钻中的电影
L1 或 L2 明细可以有自己的电影，但仅在当前层可见时运行；父电影暂停，返回后恢复原进度而非重开片头。子电影解释更细一级的信息，不复制首屏口号。明细面板高度充分，控件与返回路径固定，图表随容器 resize。关闭时清理子电影与图表，不留下原页面看不见的运行实例。

## 11. 环境动效和微交互
PPTX/HTML-PPT 的品牌装饰范围保持固定；其中 HTML-PPT 的双菱形必须小幅优雅浮动，站点式与流式 HTML 不出现双菱形。各 HTML 轨道的章节/目录/首尾玻璃卡必须小幅优雅浮动；范围由tokens约束。桌面普通指针移动必须改变局部高光，并驱动非数据阅读卡不超过±10°倾斜。呼吸、粒子、柔和光场仅作为环境层，不携带唯一信息；页面电影自动暂停时可选择一起暂停，系统减少动态或宿主静态模式必须全部停止。

禁止正式医学内容中的闪烁、故障字、霓虹、纸屑、烟花、失真、爆炸数字、随机飞字、剧烈弹簧与音效提示。不是 Dribbble 上所有效果都适合；选用连续性、空间关系和有意义的反馈，而不是炫技数量。

## 12. 无障碍和静态态
`prefers-reduced-motion`：不自动播放、不 tilt、不视差、不粒子；直接显示完整可理解的静态总览和全部必要事实。仍可点开明细、编辑甘特。提供减少透明度选项时增大散射和对比，不强迫用户读透明面上的细字。

打印/导出/截图不能因为 JS 暂停在第一帧而丢失后续内容。应使用单独的 `static_summary` 或规定总览帧，并显示需要的完整静态数据。退出 capture 后恢复之前的暂停原因与进度，不永久留在 freeze。屏幕阅读器不逐帧播数字；提供稳定目标值与图表说明。

## 13. 实现选择
轻量版本：DOM/CSS + Web Animations + 一个时间轴采样器，作为本包默认参考。复杂路径可选 GSAP 或 Motion，但每部电影只选一个叙事时钟，不强制安装新框架。已有站点使用 GSAP 时可沿用，不把本包 Film 类强塞进去重复驱动。

`runtime/kz-motion.js` 是最小可运行参考，不是全部题材的自动导演。它实现同节点几何/色彩插值、首尾检查、暂停原因、seek、RM 与清理；**关联多节点图、真实医学机制图、全部视口构图仍由具体项目实现并验收**。不可把参考 demo 能跑推断为任意站点都达到电影级效果。

## 14. 性能预算与复核
只让可见电影运行；同一像素区域最多一层实时 backdrop blur；路径采样、布局测量和读取边界不在每个粒子每一帧重复执行。选用一个载体做 width/height 形变的布局成本可接受，但要测实际帧间隔，避免大量节点同步 layout。

目标桌面 60fps、降级设备优先稳定 30fps；这是性能目标，必须给测量设备/浏览器/窗口/统计方法。长任务、截图耗时不混入帧率统计。记录 p95 帧间隔、长任务、活动 RAF 数量和离屏状态；降低反射/粒子复杂度，不降低正文可读性。合同包含移动阅读时，低功耗降级不删除必要信息；不据此给站点新增手机验收。

## 15. 强制审阅样本
至少检查：初始可读态、每段中点、每次文字切换前后、全片最大展开态、最后/首段接缝、暂停后后台返回、QC后台 seek、RM、resize、父子下钻切换、打印/静态态。录制一次完整正常速度循环，不用高速拖动假装看过。截图合格但播放眩晕/来不及读，仍不通过。

最小验收：载体 DOM 身份不变；端点属性一致；没有时间段越过保护区；自动连续推进不依赖滚动；暂停不会自己解除；静态真值完整；无控制冲突或资源泄漏。精细的视觉/叙事评分交给独立 VLM 与人工复核，不由生成者自评一句“优雅”通过。

## MOTION-01 普通HTML页面的最低动态合同（不以有无电影为条件）
每个非静态HTML任务必须读取本章。page-plan为每个可见内容对象登记唯一id、role、enter、exit、hover、ambient、data_progress、film_id、静态原因；不能只列script文件名。

| 对象 | 普通观众态必须体现 | 合法例外 |
|---|---|---|
| 正文/目录/hero玻璃卡 | 按语义顺序淡入+小位移；离开时淡出；鼠标局部光源；非数据面倾斜 | reduced-motion、触屏、打印、preview、正在编辑/选字 |
| HTML-PPT 正文双菱形（站点/流式不使用） | 固定原生样式同源；整组竖直微浮动 | 后台暂停、静态模式 |
| 目录/章节/首尾玻璃承载卡 | 微浮动；文字随同一阅读层运动 | 大号标题/Logo保持稳定；没有卡时不凭空造卡 |
| 流程节点与连线 | 按材料顺序展开，线随节点建立 | 静态模式直接完整显示 |
| ECharts/甘特 | 真正进度驱动图形和读数；结束后完整真值 | 编辑即完成动画，不覆盖修改 |
| 统计表、刻度、甘特坐标面 | 可随外组入场；自身不透视、光斑不扫过数据 | 禁止用数据面例外关闭整页的其他合法动效 |

挂载必须发生在实际交付页：`mountTilt`、`reveal`及float类/控制器各有对应对象；库存在、函数名grep或组件实验室通过不等于交付通过。结构使用layout外壳→reveal层→tilt玻璃层→reading内容；float用独立translate或再一层，任何transform只有一个owner。文字必须在卡内随卡运动，不能卡在飘字不动。

卡片的 layout/reveal 祖先默认使用平面合成，不为“立体感”随意加 `transform-style:preserve-3d`；透视由 tilt 玻璃层自身承担。真实 HTML-PPT 中该祖先属性曾使卡片变换后触发 pointerleave，立即清空光源和倾斜。只有在当前工程实际鼠标移动并驻留、完整入场与复入均通过时才可使用其他合成结构；不把本条应用到需要独立空间关系的电影舞台。QC 必须保存真实指针进入后驻留的样本与离开复位，不能只 dispatchEvent 一次读取瞬时 transform 就称 hover 通过。

上游`.is-active`观察桥只管理生命周期；enter取消旧exit并按进入序列运行，leave在上游500ms转场可见区间内执行240ms退出，再停帧；快进快退不得留下opacity=0。不得延迟或重写上游导航。对数据面保留移动高光的外壳，内部数据保持稳定。

禁止提供观众播放控制。后台暂停同时冻结环境浮动、电影和正在进行的入场到完整阅读态；系统RM、编辑、后台、非活动页原因分别管理，解除某原因不清除其他原因。preview/overview克隆/print静态完整；普通模式不能因为QC参数遗留而失去动态。

## MOTION-02 验收覆盖而非动画数量
每页至少录取进入中段、稳定态、离开中段；每类非数据卡指针实移到两角，记录transform的rotateX/Y与高光变量变化、离开复位；仅 HTML-PPT 对双菱形比较两个时刻位置，取最大扫掠区确认不撞标题；检查无可见播放器控件、后台暂停、RM、返回页面以及print。常规运动不能只看静态截图打分。流程/图表/电影分别记录序列与共用时钟；没有真实源内容不编造流程/电影凑覆盖。

### A04 计划与实际接口一致性
参考 Film 的内部接口为 pause(reason)、resume(reason)、seek(progress)、snapshot()、dispose()，均不可生成观众播放器。static_summary 是持续可阅读的内容合同，不是假定存在的对象方法；内部重置使用 seek(0)。每个状态和关系必须列 source_claim_ids（真实材料 claim 或明确 synthetic 标记）及 explanation_task，说明该段新增解释的业务关系。这些字段不能证明语义正确，仍须对照材料和正常速度全循环独立审阅。关系的 to 是目标节点 ID，开始/结束时间使用 start/end，不能复用同一字段。

### 业务状态同步与空间验收
同一时刻的标题、阶段编号、解释句、节点、关系和数值必须来自同一个业务状态选择结果；不得各自维护一套阈值表。关键帧插入停留段或改变时长后，全部消费方必须同步。使用本包 Film 时，可用 onRender 的采样帧和 index 选择内容；不可把几何关键帧的 t 直接当另一套不同步的业务阶段。采集一个正常速度全周期，并记录每次业务状态切换前/后标题、编号、说明、节点/数值快照；一处编号或含义错配即失败，几何接缝连续不能抵消。

最大展开态必须用主要空间解释业务结构，例如条目如何归组、字段如何比对、差异如何转交、输入如何形成输出。大面板只放阶段名称与一句话、其余内容永远散落在外部重复列表，不算完成信息电影。初始态可以简短；展开态按实际信息量安排节点、字段、关系与留白，不增添无来源事实。每一首屏/每个 L2 子电影都要观察完整原速周期，不能用首页一次通过替代全部。

正式观众文案禁止用“主载体、首屏电影、三阶段过程电影、组件、运行时”等词解释实现；直接写业务内容名称和必要阅读指引。这些术语只保留在私有计划和 QC。仅在目标轨道合同包含手机阅读时，手机版应保留业务流程解释；站点式 HTML 不要求手机适配。降低粒子/阴影复杂度不等于删除全部关系信息。生命周期销毁还须释放项目层增添的 ResizeObserver、window监听和延时器，不能只调用基础 Film.dispose()。
