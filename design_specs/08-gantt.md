# 08 可编辑甘特与时间语义

## 两种“可编辑”先分开 GANTT-01
HTML-PPT / 网站中的甘特必须支持实际交互：选择任务、拖动整条、拖两端延展/缩短、右侧或下方编辑器精确修改年份/季度、即时同步、撤销与还原。默认图约占 3/4，编辑器约占 1/4；空间不足改为上图下编辑器，不缩小正文。

PPTX 中“可编辑”是 PowerPoint 编辑模式下的原生时间条、标签、轴和说明，不等于浏览器中的输入框、日期吸附和 JS 联动。普通 PPTX 不自带 DOM 编辑器；本包不伪造这种能力。PPT Master 当前原生 chart schema 不接收 gantt，故使用可编辑原生形状/连接线与文本。必要时同交付交互 HTML 与 PPTX，并标明同步边界；不得把网页截图当成已完成。

## 单一时间数据 GANTT-02
任务模型：`id / label / start / end / owner / status / dependencies?`，稳定 id 不用显示名充当主键。默认季度粒度，采用整数 quarter index：`index = year × 4 + quarter - 1`。内部区间为 **[start,end)**；界面“结束季度”表示最后一个包含的季度，转换为该季度 index + 1。例：2026Q1–2026Q3 对应 `[8104,8107)`，长度 3 个季度，不是 2。

源材料为明确日期时保留日期粒度和时区规则，不擅自四舍五入成季度改变事实。年月/季度/日期的精度来自材料。没有真实结束日写不确定状态，不编造时长。引用既往研究资料的时间条默认只读；允许交互调整时建立独立“计划/情景修改层”，原始证据层不可被修改覆盖。

## 手势与表单 GANTT-03
整条拖拽保持时长，左右边缘调节 start/end。指针通过当前图表坐标反变换，不能直接用屏幕 dx 当作季度偏移；HTML-PPT 有整体 scale、浏览器缩放和 DPR 时尤为重要。设置 pointer capture，拖出条形仍可靠结束；pointercancel / Escape 回退本次拖动；微小位移视为选中而非变更。图表面在编辑时不能 tilt。

吸附季度，夹在轴边界，至少 1 个季度；更复杂日期粒度用自己的最短时间规则。禁止出现负时长、start≥end、NaN、越界或同 id 重复。左/右端有效拖拽命中区建议至少 12px，不必画成大圆把手；选中时可显示细小拖动提示。密集相邻条需防误选。

点击选择任务，编辑器同步显示开始年/季度和结束年/季度；修改后同一个数据模型触发条形与标签更新。键盘方向键移动一季度，Shift+方向键调整结束季度；表单提供等效功能，不让操作只依赖鼠标。输入无效时给具体错误，不清空原值或悄悄夹成另一个日期。

## 变更 GANTT-04
一次完整拖动是一条 undo，不每个 pointermove 占一条。表单确认是一条 undo；撤销到原始状态后 dirty 清零。还原全部必须回到原始数据，不回到某个动画中间值。默认沿用会话内修改：有变更时才出现“已修改 / 撤销 / 还原”工具条；没有修改时不常驻。**默认不新增面向受众的导出 HTML/JSON 按钮**，以免无请求扩展旧产品选择。

序列化/反序列化 API 是测试与应用适配能力，不等于向受众开放导出。持久化默认关闭；采用 localStorage 时必须处理权限失败并给恢复/丢弃选择，不能把缓存当正式保存。每次修改不改写源文献/原始内部资料。

## 动画与编辑互斥
甘特首次出现可有条形依序延伸和数字联动，但动画基于冻结的原始目标数据。用户开始选择/拖动/输入，立即停止揭示并呈现完整真值，进入编辑；电影不能覆盖编辑后的状态。返回原页面不重播覆盖修改。缩放和 redraw 后重新布置把手，不保留旧屏幕坐标。

## 测试矩阵
必须覆盖 move/左 resize/右 resize、首尾轴边界、最短一期、输入同一期、跨年、原值含未知日期、scale 0.75/1/1.5、DPR 1/2、拖拽中 resize、pointercancel、Esc、键盘、撤销、还原、序列化读回、reduced-motion、slide 离开再返回、表单焦点下箭头键不翻页。

`runtime/kz-gantt.js` 是季度、单轴参考组件，使用 ECharts custom series；日粒度、依赖自动调度、多人协同、源材料写回不是已实现能力。后续 Agent 不得把这些未实现功能写入完成清单。
