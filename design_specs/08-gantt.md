# 08 可编辑甘特与时间语义

## 编辑方式 GANTT-01
HTML 轨（HTML-PPT、站点式、流式、旗舰）的甘特在页面里直接改，不需要离开 HTML。两层：

- **页内直改**：点选条形；拖整条平移、拖两端改起止，按当前粒度吸附；←/→ 平移一个单位，Shift+←/→ 只动结束；上级泳道名前的 ▸/▾ 折叠或展开下级。有修改时图内右上角出现紧凑的“已修改 / 撤销 / 还原”条，状态提示在左下角出现约 2.6 s 后自动隐去；两者叠在甘特容器内，不撑高宿主。
- **全页编辑台**（`runtime/kz-gantt-studio.js`）：按 **T**（所有 HTML 轨；焦点在输入框时不触发）、在选中条上按回车或双击打开。页面变成编辑台，其余内容设为 inert，翻页键与滚轮不泄漏到宿主：
  - 顶栏：精度（日 / 月 / 季度）、时间轴范围、当前线（无 / 自动 / 指定）、撤销、重做、还原、保存菜单、完成；
  - 左栏：计划清单（泳道 → 阶段与里程碑），可增加、复制、上下移动、设为下级、删除；
  - 中栏：同一数据的实时预览（第二个 KZGantt，铺满可用高度），预览里同样可拖改；
  - 右栏：所选对象的属性；日期一律点选（日历：日 / 月 / 季度 / 年份四种视图），里程碑图形与图标从图标面板选。
  Esc 或“完成”关闭，焦点回到原甘特；页面上的甘特、页面数据仓库与绑定文字随每次修改同步。页面上有多个甘特时 T 打开当前的那个（依次取打开着的下钻层、HTML-PPT 的活动页、离视口中线最近的那个）。

PPTX 中的“可编辑”是 PowerPoint 编辑模式下的原生时间条、标签、轴和说明，不是浏览器里的输入框与吸附。ppt-master 的原生 chart 类型不含甘特，用可编辑原生形状与文本输出（模板 `program-plan`，13 BODY-02）。HTML 与 PPTX 由同一份计划数据生成，同步边界见 GANTT-05。

## 计划数据 GANTT-02
数据合同 `schemas/program-plan.schema.json`（结构）；语义规则由 `tools/kz_layouts/diagram_clinical.py` 的 `program_model` 与 `runtime/kz-clinical.js` 的 `KZClinical.program` 判定，两者规则、顺序与报错文字逐条相同（维护仓库的回归测试对拍）。

- 结构：`{from, to, today?, granularity?, phases?, focus?, head?, lanes:[{key, name, note?, parent?, collapsed?, bars:[{key, phase, start, end, label?, color?, status?, progress?, baseline?}], milestones:[{key, at, label, kind?, icon?, risk?, major?, baseline?}]}]}`。稳定 `key` 全局唯一，不用显示名充当主键。
- 时间写成季度 `2026Q3`、月份 `2026-08` 或日期 `2026-08-15`；结束含当个单位。内部是连续季度单位（`year × 4 + quarter − 1`，月是季度的三分之一，日是所在季度的分数），区间 **[start, end)**。时间轴按整季度对齐，覆盖 2–40 个季度。
- `granularity`（quarter / month / day）是阶段起止的精度，不写时取阶段里最细的写法；阶段不得写得比它更细。**里程碑在任何粒度下都可写到日。** 改粒度时编辑台把现有阶段起止换算到新精度（变粗时取所在单位，如 2026-08 → 2026Q3）并在状态行写明。
- 同一泳道的阶段前后相接、不得重叠，并行研究分泳道；每泳道里程碑 ≤6（多适应症总图只放关键性里程碑）；泳道 ≤24 条，同时显示 ≤12 条。
- `kind` 取 `start / readout / submit / approve / other`，各有固定图形（圆、菱、三角、星、六边形）；`icon` 可换成图标库（`assets/icons`）里的名字；`risk` 用风险色；`major` 决定收起时是否上提。
- `today`：当前时间，`auto` 取打开或构建当天；画在所写单位的中点，之后的部分按计划（浅色虚线）绘制。当前线标签用 today 自身的写法（today 比计划粗时不假装精确到月或日）。
- 源材料是明确日期时保留日期粒度，不擅自四舍五入成季度；没有真实结束日不编造时长（端点未知的阶段不进本合同，由项目另行标示“待定”）。
- 引用既往研究资料的时间条默认只读；允许调整时建立独立的“计划/情景修改层”，原始证据层不被覆盖。
- **7.x 季度形式**（`schemas/gantt.schema.json`：`{min, max, tasks, rows?, milestones?, today?, legend?}`，整数季度序号）仍可挂载、页内直改；编辑台第一次修改时经 `KZGantt.fromLegacy` 转成计划合同并提示。7.x 的通用阶段不画阶段图例，条内不写“任务”。

## 手势与表单 GANTT-03
整条拖拽保持时长，左右边缘调起止；指针通过图表坐标反变换，不能把屏幕 dx 直接当时间偏移（HTML-PPT 有整体缩放、浏览器缩放和 DPR）。用 pointer capture，pointercancel / Esc 回退本次拖动，微小位移视为选中。吸附到当前粒度、夹在轴边界内、至少一个单位；禁止负时长、start≥end、NaN、越界和重复 key；拖动与表单都夹在同一泳道前后阶段之间，写出重叠时给具体报错，不挤动邻居。平移整条时条内里程碑一起移动；只拖一端时，落在首个或末个单位内的里程碑跟随这一端。左右端命中区宽 `gantt.handle_px`（14px），短条按条宽的 `gantt.handle_short_ratio` 收窄，仍须能分别拖动两端。编辑时图表面不倾斜。

编辑台的输入无效时给具体错误（如名称不能为空、结束早于开始、与相邻阶段重叠），不清空原值，也不悄悄夹成另一个日期。

## 变更与撤销 GANTT-04
一次完整拖动是一条 undo，不是每个 pointermove 一条；编辑台的一次确认是一条 undo；撤销与重做（⌘/Ctrl+Z、⇧⌘/Ctrl+Z 或按钮）在页内与编辑台共用同一历史；撤销回保存点后 dirty 清零；“还原”回到页面载入（或上次保存）时的数据。修改不改写源文献或原始资料。

## 保存与同步 GANTT-05
- **页面数据仓库**：页面的甘特数据放在 `window.KZ_DECK_DATA[gid]`（根元素 `data-kz-gantt="<gid>"`）；每次修改写回仓库，所以翻页后重新挂载、旗舰舞台与绑定文字读到的都是最新数据。
- **草稿**：每次修改存一份到 localStorage（键 `kz-gantt-draft:<路径>:<gid>`）。下次打开编辑台时先提示“有 … 未保存的修改”，由用户选“恢复”或“丢弃”；未决定前不覆盖草稿。保存成功后删除草稿。存储失败不阻断编辑。
- **保存到本文件**：经 File System Access 选中当前这份 HTML（文件名必须一致），读出全文，只替换 `KZ_DECK_DATA` 数据块里改过的甘特条目，其余字节不动；文件里没有数据块、无法解析或没有当前甘特时拒绝写入并说明。授权后同一会话内 ⌘/Ctrl+S 直接写回。数据不在 `KZ_DECK_DATA` 里（例如站点页自带数据）或浏览器不支持时，此项禁用并说明原因。
- **导出 / 复制 / 导入 JSON**：导出的是计划合同本身；交给 Agent 后用同一份数据重建 PPTX 页（`program-plan`）与其他产物，静态模板与 HTML 的时间逐单位一致。导入经同一校验，失败不改变当前数据。

## 可选层 GANTT-06
以下各层只在数据里有对应字段时出现；没有这一块数据就不画、不占图例：

- **状态** `status`：planned / active / done / delayed / risk，条上加状态图标并进图例；
- **进度** `progress`：条内底部一道细轨（白色底轨 `gantt.progress.track` + 深橙已完成段 `gantt.progress.fill`，高 `gantt.progress.height`），条内标签后加“· N%”，图例加“进度”；不用墨色粗线（会被读成不明含义的黑条）；
- **原计划** `baseline`：与现计划不同时，阶段在条下方画一道虚线幽灵条并在后端标推迟或提前多少（+1 季度、−2 个月、+15 天）；里程碑从原计划位置引一条虚线到现位置；
- **两级泳道** `parent` / `collapsed`：下级缩进，上级名前有 ▸/▾；收起时上级显示按阶段合并的汇总条，只上提 `major`（否则递交、获批）里程碑。

**图层顺序**（下 → 上，HTML 与静态模板相同）：泳道底纹与网格 → 当前线 → 原计划幽灵条 → 阶段条（当前线前实色、后浅色虚线）→ 进度轨 → 风险与选中描边 → 状态图标与条内标签 → 里程碑及其标签（白色晕边）→ 当前线标签（轴外浅灰胶囊）。当前线是辅助参照，取 `gantt.today`（灰色虚线 `line`/`width`/`dash`，标签底 `pill`、字 `text`），不用强调色、不压条形与里程碑；常规演示（`.kz-demo-now`）与旗舰舞台用同一组颜色。

阶段色序固定取 `tokens.charts.phases`（亮度落在品牌带内的五级橙黄，相邻色差与色觉异常色差均已核对），与部门色无关；`color` 只在需要表达身份时覆盖单条。

## 绑定文字 GANTT-07
说明卡、观点句与讲稿里的日期可以绑定到计划数据，写成模板记号：`{key}`（里程碑时间或阶段起止）、`{key.start}`、`{key.end}`、`{gap:a,b}`（两点间隔，按计划粒度写成“N 个季度 / 月 / 天”）。构建时 Python `bind_text` 替换记号；HTML 输出给每个值包一层 `<span data-kz-bind="表达式">`，页面修改后 `KZGantt.bindValue` 就地更新同页（`.slide` 或最近的 `section` / `main`）的文字。未绑定的文字不会自动更新：编辑台列出同页提到改动对象（泳道名或阶段、里程碑名）的说明与讲稿，提示“可能要改的文字”。记号里的 key 不存在时构建直接报错。

## 动画与编辑互斥
首次出现时条形按 05 CHART-04 的数据缓动依次延伸（上到下小错峰），基于冻结的原始目标数据。用户开始选择、拖动或输入时立即结束揭示、呈现真值并进入编辑；返回页面不重播覆盖修改。缩放和重绘后重新布置把手，不保留旧屏幕坐标。

## 实现范围
`runtime/kz-gantt.js` 是单轴参考组件（ECharts custom series），读两种数据形式并渲染上述各层；`runtime/kz-gantt-studio.js` 是编辑台；`tools/kz_layouts/diagram_clinical.py` 输出静态模板（PPTX 原生形状与 HTML 静态版）。里程碑标签在本行内按“居中 → 左右微移 → 起止对齐 → 上移一层（≤3 层）”找空位，不压上一行的条、不压当前线标签；找不到空位的标签在 HTML 暂时不显示（图形保留），在静态模板直接报错要求缩短或拆页。依赖箭头与自动排期、多人协同、写回源材料都不是已实现能力，不得写进完成清单；“保存到本文件”需要用户在系统对话框里确认，自动化测试只覆盖数据块替换与拒绝逻辑。

## 计划总线与累计暴露 GANTT-08（round 9）
- **研究条带 `exposure`**：开发计划合同的研究条带可以带 `exposure: {n, ctrl?, exposed?, w26?, w52?, at?}`。
  - 暴露 = 样本量 × (1 − 对照比例)，按 Python 的银行家舍入，JS 的 `pyRound` 结果相同。
  - 计入时点是条带结束所在单位的起点，或 `at` 指定的时点。
  - 每个顶层泳道的第一个“递交”里程碑就是该适应症的 NDA。
  - 一个适应症有几项并行或交叠的研究（如 301 与 302）：顶层泳道是适应症，放 NDA 等注册里程碑；子泳道（`parent`）一项研究一条，各带自己的 `exposure`。源日期照写，不为消除重叠改日期。
  - 合同见 `diagram_scenes.exposure_plan` 与 `KZClinical.exposurePlan`。
- **计划总线**（`KZGantt.publish / subscribe`）：同一页里 `program.id` 相同的甘特与累计暴露图共享一份数据。
  - 任一处修改（拖动、T 编辑台、暴露图上拖动圆点），两边都跟着变。
  - `KZ_DECK_DATA` 里的计划条目与暴露图条目一起更新，带 `data-kz-xp-*` 的达标表和台账同时重绘。
  - 没有 `id` 的计划只在本图内生效。
- **累计暴露图**（HTML，`KZExposure`）：
  - 拖动研究圆点：左右移动研究条带（按条带自身精度整单位），上下调整暴露例数（步长 10）；拖动时纵轴不跳。
  - 键盘：←/→/Home/End 选研究，Shift + 方向键修改，⌘/Ctrl + Z 撤销。
  - T、回车或双击打开甘特编辑台。编辑台是离屏 KZGantt，`anchor` 为该图；属性栏里的“暴露”块可以改 n、对照比例、暴露例数、≥26 周和 ≥52 周例数。
  - 保存到本文件写回该图的 `KZ_DECK_DATA` 条目。
