# 执行计划

## 总体顺序

先验证现成产物与环境 → 两条指定引擎集成 → 小规模真实生图与电影样板 → 模型/harness 对照 → 归因修订 → 保留集回归。每阶段有独立可交付物，不等“全部跑完”才提交；不以一条巨型 shell/模型命令跑完整矩阵。

## P0 环境与最小复测

读当前本包版本/hash，探测 Python/Node/浏览器/Office/字体/图片工具以及两个上游绝对路径与 SHA。不要连续重启同一个本地模型；同一资源级别批量复用暖机进程，区分准备时间和推理时间。不要在没有错误前重新安装全部依赖。

运行本包 JSON/unit/browser 测试；本包浏览器脚本有意使用 set_content，应另补本地 HTTP 以及双击 HTML 的实际路径。验证离线依赖路径，保存控制台日志。不承诺用 `set_content` 消除了 CSP、file://、presenter 或跨窗口差异。缺项不阻止先运行可运行部分。

**产物** `runs/<id>/environment.json`、baseline test报告、变更前截图；上游/主包 hash。退出条件：可复现环境问题与组件问题已分开。

## P1 两条上游集成（最高优先级）

### P1A PPTX

必须通过 ppt-master。读取当前 route 与接口，按 `adapters/ppt-master.md` 注入。先做两页：玻璃正文卡片；原生折线+浅面积组合。实测透明度、原生高光和阴影、默认15pt与整页12pt、原生图表工作簿和图像保护区。

成功后扩为七页代表集：封面、目录、章节、密集入排、原生数据图、阶段计划、尾页。标题与关键文本必须可编辑；甘特任务形状可编辑。**在 PowerPoint 中改一个文字、一个表格单元格、一个图形，再保存回读**。本次不提供原生 Excel 支持，不通过“编辑数据”调用 Excel；图表数据采用 canonical data、缓存与嵌入工作簿的结构核对，并检查 PowerPoint 实际渲染。仅 XML 存在或 SVG 截图不算此项通过。

比较 Windows PowerPoint 与用户实际 Mac PowerPoint；无法取得其一则明确未测。额外 LibreOffice 渲染可发现兼容问题，但不能反推用户原件在原生 Office 一定出错。本次参考 PPTX 在本环境渲染出现换行/重叠，应以此设回归项，不能照抄异常效果。

### P1B HTML-PPT

必须由 html-ppt-skill scaffold。做与 PPTX 同内容的七页，复用唯一 1280×720 逻辑坐标、官方 logo、固定 header/footer/page-number 槽；不要插入第二个缩放器或全局快捷键监听器。

完成实际主题适配文件，并测试：方向键、编辑态输入、退出后翻页、hash、S 演讲者新窗口、CURRENT/NEXT iframe、notes、overview、全屏、打印。preview 使用冻结的合格静态态，不能与观众页电影各播各的而声称一致。图表和 Gantt 在翻页隐藏→显示后 resize。

**退出条件** 两个引擎各有真实产物、步骤/命令/版本、未改上游或有明确必要改动说明、已知差异表。失败仅修适配或局部材料，不降低品牌硬约束。

## P2 真实生图闭环

探测真实生图工具并实际调用；PPTX 用上游 image manifest 路线。生成前先完成排版保护 mask 和图像 brief。建议本轮最少验证封面、正文通用低噪声底图、章节、尾页四种图像任务；按实际新图数计费，不机械每页单独生成。

至少覆盖：标题左图右、密集中央卡片、有页眉页脚、含正式 logo 的合成图。每一张保存工具回执、prompt、尺寸/hash、裸图与合成图。构建故意失败样例：高光穿字、主体碰 logo、正文卡后强边、生成文字、主题不符。错误样例只用于 QC 测试，不能发布。

图像生成工具失败→修正/重试有界→BLOCKED；不要自动降级几何渐变然后记录 generated。站点全局程序化光场是唯一明确豁免，必须指出对应实现，不把普通纯色背景混充豁免。

**退出条件** 能证实真实生图、机器保护区核对与独立合成审阅串联；至少有一次“检测到失败→纠正→复审”的真实证据（没有失败则不故意捏造，可使用清楚标记的注入故障样例验证检测器）。

## P3 电影、宽屏与下钻

基础 Film 只是几何时钟。补一个真正业务信息电影：研究流程或证据组织均可，材料由用户授权/合成 fixture 提供；至少三段明确关系变化，持续同一主载体，子信息依序展开，首尾回到同一语境。不用新物体替换旧物体，不让 ScrollTrigger/GSAP/Film 两个时钟争夺属性。

站点和流式各做首页+一级章节首屏。全局场景图至少88%视口宽，阅读行长单独限制。站点只验收桌面 1280×720、1440×900、1920×1080、2560×1080，不做手机/窄屏阅读适配；流式保留其桌面与390px阅读检查。电影要正常速度完整录一圈；检查最后300ms和开头300ms、文字阅读停留、最大扫掠区、离屏、进入明细后的后台暂停、减少动态、resize、静态详情，不设置观众播放器。站点重点参考用户授权的 ARCO 动画与交互，但须以实际文件和渲染证明机制；不复制内部业务数据进通用 skill。

下钻 L1 至少两个有用信息区域（例如图表+方法），L2 继续更深入；同一宽弹层内有面包屑、焦点/滚动恢复、子动画暂停清理。原有小型tooltip可以保留作值提示，但不算“信息下钻”。

Gantt 复测移动/两端拉伸/表单/边界/取消/键盘/撤销/resize/缩放；增加多密度案例与 HTML-PPT 活动页测试。编辑开始前结束或暂停入场动画，不能覆盖用户修改。默认无导出按钮。

## P4 多模型与 harness 对照

按 EVALUATION.md 进行。先12次 pilot，再依据失败分布扩样；不要一上来做数百次大模型+全视频审阅。保留模型弱能力失败本身，不用 coordinator 静默补完后把修复后文件计为该模型成功。

## P5 修订与释放

每次只改变一个归因假设：规则消歧/示例/检索路由/模型/实现，尽量保持其他条件一致。重新生成受影响样本，再在未用于调整的保留集回归。修改 rule owner、schema、runtime、fixtures、README 中必要项，删除过时条款。

最终交付单一 skill zip、明确的测试状态表、原始数据索引、失败列表和新版 handoff。存在可复现关键失败时状态为 `PARTIAL` 或 `BLOCKED`，不能把没有测的平台写为通过。
